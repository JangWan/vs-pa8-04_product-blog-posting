# Usecase — 인증 (회원가입·로그인·비밀번호찾기·로그아웃)
> UC-02~05 | 작성일: 2026-05-15 | 참조: PRD.md · IA.md · TRD.md · usecase-common.md

---

## 1. 개요

| UC | 기능명 | 한 줄 설명 | 행위자 |
|----|--------|---------|--------|
| UC-02 | 회원가입 | 이메일+비밀번호로 계정을 생성하고 이메일 인증을 완료한다 | `Visitor` |
| UC-03 | 로그인 | 이메일+비밀번호로 인증하여 대시보드에 진입한다 | `Visitor` |
| UC-04 | 비밀번호 찾기 | 이메일로 비밀번호 재설정 링크를 받아 변경한다 | `Visitor` |
| UC-05 | 로그아웃 | 현재 세션을 종료하고 랜딩 페이지로 이동한다 | `User` |

**구현 방식**: Clerk Elements (`@clerk/elements/sign-in`, `@clerk/elements/sign-up`)로 shadcn/ui 커스텀 UI 구성. Clerk Prebuilt UI 미사용.  
**인증 방법**: 이메일 + 비밀번호 (MVP 범위, 소셜 로그인 미지원 — TRD §3-5 참조)  
**users 테이블 동기화**: 회원가입 완료 후 Clerk Webhook(`user.created`)이 `POST /api/webhooks/clerk`로 이벤트를 전달하면 서버가 `users` 테이블에 자동 INSERT. 클라이언트에서 별도 API 호출 불필요.

## 3. 정상 흐름

### UC-02 — 회원가입

| 단계 | 행동 주체 | 내용 |
|------|---------|------|
| 1 | Visitor | `/sign-up` 접근 또는 랜딩 "시작하기" CTA 클릭 → `/sign-up` 이동. |
| 2 | 시스템 | Clerk Elements 기반 회원가입 폼 렌더링. 입력 필드: 이메일, 비밀번호, 비밀번호 확인. |
| 3 | Visitor | 이메일, 비밀번호(8자 이상), 비밀번호 확인 입력 후 "회원가입" 버튼 클릭. |
| 4 | 시스템 | Clerk Elements가 입력값 유효성 검사 (형식·길이). 오류 시 인라인 에러 표시 (→ 예외 흐름 5-1). |
| 5 | 시스템 | Clerk API에 회원가입 요청. 성공 시 가입된 이메일로 인증 코드(6자리 OTP) 발송. |
| 6 | 시스템 | 이메일 인증 코드 입력 폼으로 전환 (동일 페이지 `/sign-up` 내). |
| 7 | Visitor | 수신한 이메일에서 6자리 OTP 코드 확인 후 입력 필드에 입력. |
| 8 | 시스템 | Clerk API에 OTP 검증 요청. 성공 시 세션 생성. Clerk가 비동기로 `user.created` 이벤트를 `POST /api/webhooks/clerk`로 발송 → 서버가 이벤트 수신 후 `users` 테이블에 INSERT (`clerk_user_id`, `email`, `plan: 'free'`). 이 INSERT는 리다이렉트와 별개로 비동기 처리됨. |
| 9 | 시스템 | `/dashboard`로 리다이렉트. 신규 사용자이므로 대시보드 Empty State 표시 (→ usecase-대시보드 참조). |

### UC-03 — 로그인

| 단계 | 행동 주체 | 내용 |
|------|---------|------|
| 1 | Visitor | `/sign-in` 접근. `redirect` 파라미터가 있으면 URL에 포함 (`/sign-in?redirect=/generate`). |
| 2 | 시스템 | Clerk Elements 기반 로그인 폼 렌더링. 입력 필드: 이메일, 비밀번호. |
| 3 | Visitor | 이메일, 비밀번호 입력 후 "로그인" 버튼 클릭. |
| 4 | 시스템 | Clerk API에 인증 요청. 성공 시 JWT 세션 쿠키 발급. |
| 5 | 시스템 | `redirect` 파라미터가 있으면 해당 경로로 이동. 없으면 `/dashboard`로 이동. |

### UC-04 — 비밀번호 찾기

| 단계 | 행동 주체 | 내용 |
|------|---------|------|
| 1 | Visitor | 로그인 폼(`/sign-in`)의 "비밀번호를 잊으셨나요?" 링크 클릭. |
| 2 | 시스템 | 비밀번호 재설정 이메일 입력 폼으로 전환 (동일 페이지 `/sign-in` 내 Clerk Elements 단계 전환). |
| 3 | Visitor | 가입 시 사용한 이메일 입력 후 "재설정 이메일 발송" 버튼 클릭. |
| 4 | 시스템 | Clerk API에 비밀번호 재설정 요청. 해당 이메일로 재설정 링크 발송. |
| 5 | 시스템 | "이메일을 확인하세요." 안내 메시지 표시. |
| 6 | Visitor | 이메일의 재설정 링크 클릭 → Clerk 호스팅 재설정 페이지로 이동. |
| 7 | Visitor | 새 비밀번호 입력 후 확인. |
| 8 | 시스템 | 비밀번호 업데이트 완료 → `/sign-in`으로 리다이렉트 + "비밀번호가 변경되었습니다." 안내. |

### UC-05 — 로그아웃

| 단계 | 행동 주체 | 내용 |
|------|---------|------|
| 1 | `User` | Sidebar 하단의 Clerk `<UserButton>` 클릭 → 드롭다운 메뉴 표시. |
| 2 | `User` | "로그아웃" 항목 클릭. |
| 3 | 시스템 | Clerk API 세션 종료. JWT 쿠키 삭제. |
| 4 | 시스템 | `/`(랜딩 페이지)로 리다이렉트 (BR-14). |

## 4. 대안 흐름

### 4-1. 이미 로그인된 상태로 `/sign-in` 또는 `/sign-up` 접근 (BR-03)

## 5. 예외 흐름

- **공통 예외** (네트워크 오류·서버 오류): usecase-common.md §3 참조

### 5-1. 이메일 형식 오류 또는 필수 항목 미입력

| 조건 | 처리 |
|------|------|
| 이메일 형식 오류 | 해당 필드 하단 인라인 에러: "올바른 이메일 형식을 입력해주세요." |
| 비밀번호 8자 미만 | 인라인 에러: "비밀번호는 8자 이상이어야 합니다." |
| 비밀번호 불일치 | 인라인 에러: "비밀번호가 일치하지 않습니다." |
| 필수 항목 미입력 | 인라인 에러: "필수 항목입니다." |

### 5-2. 이미 가입된 이메일로 회원가입 시도

| 조건 | 처리 |
|------|------|
| 중복 이메일 | Clerk 오류 반환 → 인라인 에러: "이미 사용 중인 이메일입니다. 로그인해주세요." + `/sign-in` 링크 표시. |

### 5-3. 로그인 실패 (잘못된 이메일·비밀번호)

| 조건 | 처리 |
|------|------|
| 인증 실패 | Clerk 오류 반환 → 인라인 에러: "이메일 또는 비밀번호가 올바르지 않습니다." (보안상 구체적 원인 미노출) |
| 5회 연속 실패 | Clerk 계정 일시 잠금 → 인라인 에러: "로그인 시도 횟수를 초과했습니다. 잠시 후 다시 시도해주세요." |

### 5-4. OTP 코드 만료 또는 오류 (UC-02)

| 조건 | 처리 |
|------|------|
| OTP 만료 (10분) | 인라인 에러: "인증 코드가 만료되었습니다. 코드를 다시 받아주세요." + "코드 재발송" 버튼. |
| OTP 불일치 | 인라인 에러: "인증 코드가 올바르지 않습니다." |

### 5-5. 비밀번호 재설정 — 가입되지 않은 이메일 (UC-04)

| 조건 | 처리 |
|------|------|
| 미가입 이메일 | 보안상 동일 메시지 표시: "이메일을 확인하세요." (계정 존재 여부 노출 금지) |

## 7. UI/UX 고려사항

- **공통 UI 패턴**: usecase-common.md §4 참조
- **Clerk Elements 커스텀 UI**: shadcn/ui `<Input>`, `<Button>`, `<Label>`, `<FormMessage>` 컴포넌트 사용. Notion 디자인 토큰 적용.
- **레이아웃**: 인증 레이아웃 (`AuthLayout`) — 화면 중앙 정렬 카드(max-w-md). PublicHeader·Footer 미표시.
- **에러 표시**: Clerk Elements의 `<FieldError>`를 shadcn/ui `<FormMessage>` 스타일로 오버라이드.
- **"비밀번호를 잊으셨나요?" 링크**: 로그인 폼 비밀번호 필드 우측 하단. Muted 텍스트 색상(`#a39e98`).
- **회원가입 ↔ 로그인 전환**: 각 페이지 하단 "이미 계정이 있으신가요? 로그인" / "계정이 없으신가요? 회원가입" 텍스트 링크.
- **버튼 로딩 상태**: 제출 중 버튼 비활성화 + `<Loader2>` 스피너.
