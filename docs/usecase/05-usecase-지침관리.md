## 1. 개요

|----|--------|---------|---------|

## 3. 정상 흐름

### UC-10 — 지침 목록 조회

| 단계 | 행동 주체 | 내용 |
|------|---------|------|
| 1 | `User` | `/guidelines` 접근 (Sidebar "AI 지침 관리" 클릭). |
| 2 | 시스템 | `GET /api/guidelines` 호출로 사용자의 지침 전체 목록 조회. |
| 3 | 시스템 | 로딩 중 스켈레톤 카드 표시. |
| 4 | 시스템 | 지침 카드 목록 렌더링 (Framer Motion stagger 등장): |
| | | • 제목 |
| | | • 내용 미리보기 (최대 2줄 말줄임) |
| | | • 기본 지침 여부 Badge (`기본` — Sage Green) |
| | | • 카드 우측: "기본으로 설정" 토글 버튼 + "수정" 버튼 + "삭제" 버튼 |
| 5 | `User` | 목록 확인. 카드 액션 버튼 클릭으로 UC-12·13·14 진행. |

### UC-11 — 지침 생성

| 단계 | 행동 주체 | 내용 |
|------|---------|------|
| 1 | `User` | `/guidelines` 우상단 "+" 버튼 클릭 → `/guidelines/new` 이동. |
| 2 | 시스템 | 지침 생성 폼 렌더링: 제목 Input + 내용 Textarea (2000자 이내). |
| 3 | `User` | 제목(필수) + 내용(필수) 입력. |
| 4 | `User` | "저장" 버튼 클릭. |
| 5 | 시스템 | 클라이언트 유효성 검사 (필수 항목·길이). 통과 시 "저장 중..." 버튼 상태로 전환. |
| 6 | 시스템 | `POST /api/guidelines` 요청: `{ title, content, is_default: false }`. |
| 7 | 시스템 | `guidelines` 테이블 INSERT. 201 응답 반환. |
| 8 | 시스템 | `/guidelines`로 리다이렉트. "지침이 저장되었습니다." 성공 토스트. |

### UC-12 — 지침 수정

| 단계 | 행동 주체 | 내용 |
|------|---------|------|
| 1 | `User` | 지침 카드의 "수정" 버튼 클릭 → `/guidelines/[id]` 이동. |
| 2 | 시스템 | `GET /api/guidelines/:id` 호출. 소유권 확인 (PC-06). |
| 3 | 시스템 | 수정 폼 렌더링: 기존 제목·내용 데이터 채워진 상태. |
| 4 | `User` | 내용 수정 후 "저장" 버튼 클릭. |
| 5 | 시스템 | 클라이언트 유효성 검사 통과 시 "저장 중..." 상태 전환. |
| 6 | 시스템 | `PUT /api/guidelines/:id` 요청: `{ title, content }`. |
| 7 | 시스템 | `guidelines` 테이블 UPDATE (`title`, `content`, `updated_at`). 200 응답. |
| 8 | 시스템 | `/guidelines`로 리다이렉트. "지침이 저장되었습니다." 성공 토스트. |

### UC-13 — 지침 삭제

| 단계 | 행동 주체 | 내용 |
|------|---------|------|
| 1 | `User` | 지침 카드의 "삭제" 버튼 클릭. |
| 2 | 시스템 | shadcn/ui `<AlertDialog>` 표시: |
| | | 제목: "정말 삭제하시겠습니까?" |
| | | 본문: "이 지침을 삭제하면 해당 지침으로 생성된 이력에서 지침명이 '삭제된 지침'으로 표시됩니다." |
| | | 버튼: [취소 (secondary)] [삭제 (destructive)] |
| 3 | `User` | "삭제" 버튼 클릭. |
| 4 | 시스템 | `DELETE /api/guidelines/:id` 요청. 소유권 확인 (PC-06). |
| 5 | 시스템 | `guidelines` 테이블 DELETE. 연관 `contents.guideline_id` → NULL 업데이트 (BR-12). |
| 6 | 시스템 | `AlertDialog` 닫힘. 목록에서 해당 카드 제거 (낙관적 업데이트 또는 재조회). "지침이 삭제되었습니다." 성공 토스트. |

### UC-14 — 기본 지침 설정

| 단계 | 행동 주체 | 내용 |
|------|---------|------|
| 1 | `User` | 기본으로 설정하려는 지침 카드의 "기본으로 설정" 버튼 클릭. |
| 2 | 시스템 | 이미 기본 지침인 경우 → 대안 흐름 4-1. |
| 3 | 시스템 | `PUT /api/guidelines/:id` 요청: `{ is_default: true }`. |
| 4 | 시스템 | DB 트랜잭션: 기존 `is_default=true` 레코드 → `false` 업데이트 후, 대상 레코드 → `true` 업데이트 (BR-11). |
| 5 | 시스템 | 목록 갱신: 변경된 카드의 Badge·버튼 상태 즉시 업데이트. "기본 지침으로 설정되었습니다." 성공 토스트. |

## 7. UI/UX 고려사항

- **공통 UI 패턴**: usecase-common.md §4 참조

**지침 목록 카드 (`/guidelines`)**

| 요소 | 스펙 |
|------|------|
| 카드 레이아웃 | 1열 리스트. 카드 Radius 8px, Whisper Border. |
| 기본 지침 Badge | Sage Green(`#99d1aa`) 배경 + 흰색 텍스트 "기본". |
| "기본으로 설정" 버튼 | Ghost 스타일. 이미 기본 지침이면 버튼 비활성화 + "기본 지침" 텍스트. |
| "수정" / "삭제" 버튼 | 카드 우측 상단. 수정: Ghost, 삭제: Ghost + destructive 텍스트 색상. |
| 카드 등장 | Framer Motion `staggerChildren: 0.05`, `opacity: 0→1`. |
| 우상단 "+" 버튼 | `/guidelines/new` 이동. Sage Green Primary. |

**지침 생성·수정 폼 (`/guidelines/new`, `/guidelines/[id]`)**

| 요소 | 스펙 |
|------|------|
| 제목 Input | shadcn/ui `<Input>`. 최대 100자. 글자 수 카운터 표시. |
| 내용 Textarea | 최소 높이 200px, 자동 높이 확장. 우측 하단 글자 수 카운터 (`현재/2000`). |
| 저장 버튼 | Sage Green Primary. 저장 중 비활성화 + "저장 중..." 텍스트. |
| 취소 버튼 | Ghost 스타일. `/guidelines`로 이동. |
| 페이지 상단 | breadcrumb: `AI 지침 관리 / 새 지침` 또는 `AI 지침 관리 / {제목}`. |

**삭제 확인 AlertDialog**

```
[제목] 정말 삭제하시겠습니까?
[본문] 이 지침을 삭제하면 해당 지침으로 생성된 이력에서
       지침명이 '삭제된 지침'으로 표시됩니다.
[버튼] [취소]  [삭제]
```

## 8. 데이터 요구사항

### 입력 데이터 (UC-11·12)

| 필드 | 타입 | 필수 | 검증 규칙 |
|------|------|------|---------|
| `title` | string | ✅ | 1자 이상, 100자 이내 |
| `content` | string | ✅ | 1자 이상, 2000자 이내 |
| `is_default` | boolean | ❌ | 생성 시 항상 `false` (목록 카드 토글로만 변경) |

### API 엔드포인트

| 메서드 | 엔드포인트 | 용도 |
|--------|-----------|------|
| `GET` | `/api/guidelines` | 지침 목록 조회 (UC-10) |
| `POST` | `/api/guidelines` | 지침 생성 (UC-11) |
| `PUT` | `/api/guidelines/:id` | 지침 수정 또는 기본 설정 변경 (UC-12·14) |
| `DELETE` | `/api/guidelines/:id` | 지침 삭제 (UC-13) |

### 출력 데이터 (UC-10)

| 필드 | 설명 |
|------|------|
| `id` | 지침 고유 ID |
| `title` | 지침 제목 |
| `content` | 지침 내용 (미리보기: 최대 2줄) |
| `is_default` | 기본 지침 여부 |
| `created_at` | 생성일 |
| `updated_at` | 최종 수정일 |

## 9. 보안 및 권한

| 항목 | 내용 |
|------|------|
| 접근 권한 | `User` 전용 (Clerk 미들웨어 보호) |
| 데이터 소유권 | 모든 API에서 JWT `userId` 기준 필터링. 타인 지침 접근 시 403 반환 (BR-04) |
| 입력 검증 | Hono Zod 스키마로 `title` 100자·`content` 2000자 서버 측 재검증 (BR-07) |
| XSS 방지 | 지침 내용은 AI 시스템 프롬프트에 삽입되므로 HTML 이스케이프 처리 (BR-08) |
| 기본 지침 변경 트랜잭션 | `is_default` 업데이트는 단일 DB 트랜잭션으로 처리하여 동시성 문제 방지 (BR-11) |
