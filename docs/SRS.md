# [Phase 3] 조직 관리 및 AI Agent 자동화 최종 요구사항 정의서

> **작성일:** 2026-05-17  
> **상태:** 최종 확정 (Final)  
> **대상 범위:** 조직(팀) 관리, 멀티 테넌시 구축, AI Agent 자동화 파이프라인

## 1. 조직(팀) 관리 및 멀티 테넌시 (Multi-tenancy)

### 1.1 개요

개인 단위 서비스에서 기업 및 팀 단위 B2B SaaS로 확장하기 위한 핵심 기반을 구축합니다. 모든 자원(콘텐츠, 지침, 에이전트)은 특정 '조직'에 귀속되며, 권한에 따라 공유됩니다.

### 1.2 핵심 요구사항

- **멀티 테넌시 구조:** 모든 데이터는 `organization_id`를 기준으로 격리됩니다. 사용자는 여러 조직에 소속될 수 있으며, 사이드바에서 조직을 전환하며 작업합니다.
- **조직 생성 및 관리:**
  - 로그인한 모든 사용자는 새 조직을 생성할 수 있습니다.
  - 조직 생성자는 자동으로 `org:admin` 역할을 가집니다.
- **멤버 초대 및 권한 (RBAC):**
  - **Admin:** 조직 설정 변경, 멤버 초대/추방, 결제 관리, 모든 자원 수정/삭제 권한.
  - **Member:** 공유된 지침 사용, 콘텐츠 생성, 에이전트 실행 권한 (조직 설정 및 멤버 관리 불가).
- **공유 지침 (Option A 채택):**
  - 작성된 AI 지침은 해당 조직 내의 모든 멤버가 공유합니다.
  - 누가 작성했든 조직 내 멤버라면 동일한 브랜드 톤 지침을 사용하여 콘텐츠를 생성할 수 있습니다.

### 1.3 기존 데이터 보존 및 백필(Backfill) 전략

- **Personal Organization 도입:** 모든 기존 사용자는 가입 시 자신의 이메일 기반 '개인 조직(Personal Org)'을 자동으로 할당받습니다.
- **데이터 이관 (Backfill):** 조직 기능 도입 전 작성된 모든 `contents`와 `guidelines` 데이터는 마이그레이션 시 해당 사용자의 '개인 조직' ID로 일괄 귀속됩니다.
- **무중단 서비스:** 사용자는 평소처럼 로그인하되, 내부적으로는 '개인 조직' 컨텍스트에서 작업을 시작하게 되어 데이터 유실을 전혀 느끼지 못합니다.

## 2. AI Agent 자동화 (Automation)

### 2.1 개요

사람의 개입 없이도 주기적으로 블로그 주제를 발굴하고 글을 완성하는 '자율형 비서' 기능을 구현합니다. 단순한 챗봇을 넘어 **Tool Calling(도구 호출)** 능력을 갖춘 시스템으로 구축합니다.

### 2.2 핵심 요구사항

- **스케줄링 기반 자동화:** 사용자가 설정한 주기(예: 매주 월요일 9시)에 맞춰 에이전트가 자동으로 깨어나 작업을 수행합니다. (Vercel Cron 활용)
- **3단계 자동화 파이프라인:**
  1.  **주제 수집 (Topic Discovery):** 사용자가 등록한 시드 키워드를 바탕으로 LLM이 새로운 글감을 스스로 발굴합니다.
  2.  **초안 작성 (Auto Generation):** 발굴된 주제와 조직 내 공유된 지침을 결합하여 블로그 본문을 작성합니다.
  3.  **발행 연동 (Publishing - Phase 3 확장):** 작성된 초안을 Hashnode, Medium 등 외부 플랫폼에 Draft(임시저장) 상태로 직접 전송합니다.
- **실행 이력 모니터링:** 에이전트가 언제, 어떤 주제로 글을 썼는지, 성공했는지 실패했는지 확인할 수 있는 전체 로그 페이지를 제공합니다.

### 2.3 Agent 전용 도구(Tools) 정의

에이전트가 작업을 수행하기 위해 호출하는 핵심 기능들입니다.

- **Topic Picker:** 시드 키워드를 인풋으로 받아 중복되지 않은 주제를 아웃풋으로 내놓는 도구.
- **Content Writer:** 주제와 지침 ID를 받아 마크다운 본문을 생성하는 도구.
- **Platform Publisher:** 마크다운 본문을 외부 API로 쏴주는 도구.

## 3. 주요 비즈니스 규칙 (Business Rules)

- **BR-31 (조직 소유권):** 모든 콘텐츠는 반드시 하나의 조직에 속해야 합니다. 조직 삭제 시 해당 조직의 모든 콘텐츠는 30일간 유예 기간 후 완전 삭제됩니다.
- **BR-32 (플랜별 한도):**
  - Free 플랜: 멤버 1명, 월 생성 10회, 에이전트 사용 불가.
  - Pro 플랜: 멤버 3명, 월 생성 200회, 에이전트 3개 활성화 가능.
- **BR-33 (에이전트 스케줄):** 최소 실행 간격은 1시간입니다. 무한 루프나 시스템 과부하를 방지하기 위해 5분 단위 Cron 체크를 수행합니다.
- **BR-34 (지침 공유 범위):** 조직 내에서 생성된 모든 지침은 '조직 공용'으로 취급됩니다. 개인만 보고 싶은 지침은 '개인 조직'에서 작성해야 합니다.

## 4. UI/UX 요구사항 (IA 보완 가이드)

- **Sidebar 수정:** 상단에 Clerk `<OrganizationSwitcher>`를 배치하여 사용자가 현재 어떤 조직에서 일하고 있는지 명확히 인지하게 합니다.
- **관리자 메뉴 분리:** 조직 설정, 멤버 관리, 결제 정보는 `org:admin`에게만 사이드바 메뉴로 노출됩니다.
- **에이전트 대시보드:** 현재 활성화된 에이전트 목록, 다음 실행 예정 시간, 최근 성공/실패 여부를 카드 형태로 한눈에 보여줍니다.
