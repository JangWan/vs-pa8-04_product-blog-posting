# [BR-03] 조직 관리 및 멀티 테넌시 정책

이 문서는 IndiePost AI의 조직(팀) 관리 기능에 대한 최종 비즈니스 규칙 및 구현 지침을 정의합니다. 모든 개발은 본 문서의 **SSOT(단일 진실 공급원)** 원칙을 준수해야 합니다.

## 1. URL 구조 및 네비게이션

- **고정 URL 유지 (IA/TRD 유지):** 조직별로 URL이 바뀌지 않습니다. `/dashboard`, `/generate` 등의 경로는 고정되며, 표시되는 데이터는 Clerk의 **OrganizationSwitcher**에 의해 결정된 '현재 활성 조직(Active Organization)'의 컨텍스트를 따릅니다.
- **경로 명칭:** 조직 관리 관련 설정 페이지의 기본 경로는 기존 `/org`에서 **`/org`**로 변경합니다. (예: `/org/new`, `/org/[id]/members`)
- **Switcher 연동:** 사이드바 상단에 Clerk `<OrganizationSwitcher />`를 배치하여 사용자가 자유롭게 작업 컨텍스트를 전환하도록 합니다.

## 2. 조직 생성 및 온보딩 (Personal Org)

- **Personal Org 자동 생성:** 신규 유저 가입 시(`user.created` 웹훅), 시스템은 해당 유저를 위해 **"유저명's Workspace"**라는 개인 조직을 자동으로 생성합니다.
- **기존 데이터 백필(Backfill):** 조직 기능 도입 전의 모든 `contents` 및 `guidelines` 데이터는 마이그레이션 시 해당 소유자의 'Personal Org' ID로 귀속되어 데이터 미아 발생을 방지합니다.
- **기본 조직 설정:** `users.default_organization_id` 필드를 통해 유저가 마지막으로 접속했던 조직을 기억하고 자동 진입시킵니다.

## 3. 멤버 초대 및 권한 정책

- **초대 기반 멤버십 (보안 유지):** 조직에 멤버를 추가할 때는 이메일을 통한 **Invitation(초대)** 방식을 사용합니다. 상대방이 초대 이메일을 수락해야만 조직의 멤버가 됩니다.
- **역할(Role) 구분:**
  - `org:admin`: 조직 정보 수정, 멤버 초대/제거/역할 변경, 조직 삭제, 결제 관리.
  - `org:member`: 조직 내 콘텐츠 및 지침 읽기/쓰기/공유, 에이전트 실행.
- **공유 지침 (Option A):** 모든 AI 지침(`guidelines`)은 조직 단위로 소유됩니다. 조직 내 모든 멤버는 동일한 지침을 보고 편집하며 생성에 사용할 수 있습니다.

## 4. 조직 삭제 및 데이터 보관 (Grace Period)

- **30일 유예 정책 (SRS/IA 유지):** 조직 삭제 시 데이터는 즉시 파괴되지 않습니다.
  - 삭제 요청 시 상태가 `deleted`로 변경되며, 30일간의 **유예 기간(Grace Period)**이 시작됩니다.
  - 30일 이내에는 관리자가 삭제를 취소하고 복구할 수 있습니다.
  - 30일이 경과하면 시스템(Upstash QStash 트리거)에 의해 해당 조직과 관련된 모든 데이터(콘텐츠, 지침, 에이전트 등)가 CASCADE 방식으로 완전 삭제됩니다.
- **삭제 확인 절차:** 삭제 요청 시 조직의 `Slug`를 직접 입력하게 하여 의도치 않은 삭제를 방지합니다.

## 5. 멀티 테넌시(Multi-tenancy) 구현 지침

- **데이터 격리:** 백엔드(Hono)의 모든 조회 API는 `auth().orgId` 필터를 필수적으로 적용합니다. 자신의 활성 조직이 아닌 `organization_id`를 가진 데이터에 접근하려 할 경우 `404 Not Found`를 반환하여 데이터 유출을 원천 차단합니다.
- **DB 인덱스:** 모든 주요 테이블의 `organization_id` 컬럼에 인덱스를 생성하여 대규모 데이터 환경에서도 빠른 조회가 가능하도록 합니다.
